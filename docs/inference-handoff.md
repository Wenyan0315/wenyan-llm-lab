## 教学目标（按优先级）

1. 建立推理的性能模型：prefill 与 decode 的区别、memory-bound 与 compute-bound、TTFT / TPOT / 吞吐 / 尾延迟的定义与测量。
2. 能手写 KV Cache，并用数值一致性证明它没算错。
3. 能算清 KV Cache 的显存账本，解释 batch、序列长度、层数、头数、数据类型如何影响它。
4. 能解释并实测量化（int8 / int4）的精度—显存—速度三角。
5. 能用成熟引擎跑固定 workload：本地 llama.cpp，云端 vLLM，做同条件对比。
6. 能做一次像样的 profiling，指出瓶颈并验证一项优化。
7. 能把服务接到 facta，并保留质量与性能对照。

## 建议课程顺序

每课 60–90 分钟，先讲全景再下钻；每课只聚焦 1 个原理 + 1 个可观察实验。

- L1 性能模型与基线：定义指标，跑一次未优化的生成，记录基线。
- L2 手写 KV Cache：从"每步重算"到"缓存复用"，做数值一致性 + 显存账本。
- L3 prefill / decode 分项测量：为什么 decode 慢，roofline 直觉。
- L4 batching：静态批 → 连续批的概念与模拟，吞吐—延迟曲线。
- L5 量化原理与实测：对称 / 分组、int8 / int4，困惑度与速度。
- L6 llama.cpp 本地实测（Metal）。
- L7 vLLM 云端实测（PagedAttention、continuous batching）。
- L8 profiling：找瓶颈并验证一项优化。
- L9 服务化与压测：OpenAI 兼容 API、并发、错误处理。
- L10 facta 接入 + 作品集整理。

## 测量纪律（求职作品集的核心）

每次实验必须记录：

- 硬件、OS、Python / PyTorch / 引擎版本
- 模型 revision、量化方式、tokenizer revision
- batch size、prompt 长度、生成长度、并发数
- TTFT、TPOT、tokens/s、峰值内存
- 重复次数与中位数（至少 3 次，不用单次下结论）
- 原始日志路径

跨机器、跨量化、跨引擎比较时，必须同模型、同 prompt、同生成长度；不拿不同 tokenizer 的 perplexity 直接比大小。

## 面试映射

这条线的每次实验都要能对应一个面试问题，例如：

- KV Cache 占多少显存，怎么算？
- prefill 和 decode 为什么性能特征不同？
- 量化为什么能省显存但未必更快？
- continuous batching 解决了什么，代价是什么？
- 线上尾延迟高，你怎么定位？
