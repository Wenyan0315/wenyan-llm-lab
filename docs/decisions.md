## D-001 · 2026-10-18 · 时间线压缩为周末冲刺型（10–12 周）

- **决策**：放弃 SPEC 建议的 20–24 周均匀节奏，改为"周末集中学习 + 平时机器跑任务"，目标 10–12 周毕业。
- **理由**：本人实际节奏为周末大块时间（每周 15–25h）、周中基本无时间；总量约 180h ÷ 每周末 ~18h ≈ 10 个学习周末。
- **被否掉的替代项**：4 周完成（需要每周 45h+，不可行）；维持 20–24 周（时间利用率低）。
- **影响**：全部里程碑（M1–M11）按"周末 N"排期；M3/M6 的训练利用周五晚启动；某个周末失约则整体顺延并如实标 deferred。**验收标准不随压缩降低**（SPEC 红线）。

## D-002 · 2026-10-18 · 教学模式确认为"AI 写实现 + 本人阅读验证"

- **决策**：M0 的"学习者独立完成线性分类器"按 SPEC 弱基础适配规则执行为：agent 写完整最小实现，本人负责阅读追踪、shape 推导、预测和小修改，不以白纸手写为通过条件。
- **理由**：本人明确选择"你写我读"，自述完全不了解 PyTorch 用法；SPEC 第 6 节弱基础适配规则优先于字面"独立完成"。
- **被否掉的替代项**：从零手写（本人拒绝且 SPEC 允许豁免）；纯运行不解读（违反"跑通≠学会"红线）。
- **影响**：后续所有里程碑的"学习者独立完成"项均按此模式执行；理解验收仍以本人解释/预测/排错的独立证据为准，M11 毕业答辩含不看参考答案补全关键片段。

## D-003 · 2026-10-18 · 开源模型基线从 M0 推迟到 M6

- **决策**：M0 的"先跑一次开源模型原始输出"项推迟到 M6 建立 Base 基线时一并完成。
- **理由**：避免在学习首日下载 0.6B 模型；M6 本来就要建立 Base 基线，属同一动作。
- **影响**：M0 验收不含此项（已在 docs/baseline.md 未完事项注明）；M6 前置检查增加"验证 Base 模型可下载性与版本兼容"。
